# Databento API and qualification — EQ069

Canonical [EQ069 #78](https://github.com/atulsrivas1/equity-features/issues/78), component [PR15](https://github.com/atulsrivas1/equity-feature-io/pull/15). Implementation is in progress. This document records the supported surface and preliminary local evidence; native qualification, final source review and actual provider proof remain required. No release/acceptance claim.

`DatabentoProfile` freezes dataset (`VENUE.FEED`), schema (`trades` or `ohlcv-1m`), namespace, source binding, `PriceUnit(9, currency)`, canonical event `InputScope`, separate capture bounds, explicit publisher/instrument→canonical instrument/session/eligibility bindings and optional original known-at annotations. The full profile SHA256 enters acquisition scope and source identity. `DatabentoHistoricalAdapter` requires caller approval and credential injection; `cost_upper_micro_usd=None` is default deny. This argument is trusted application evidence, not a provider cost estimate, billing query or permission. A zero-budget request requires verified zero-cost entitlement and scoped owner authorization.

Factory protocol1 uses only `{'profile_id': profile.fingerprint}` public configuration; register explicitly in existing `SourceRegistry`. `create` receives a `CredentialProvider`, without retrieving the key. Request instrument and session sets and event bounds must match the frozen profile exactly; mismatches fail before credentials/transport. A new population needs its own profile/approval. One adapter instance supports one iteration attempt, including denial/cancellation/failure; concurrent and repeated use reject. Trusted applications must allocate fresh budgets across instances. No credential, URL, dynamic import or network setting belongs in public config. [Owned factory and pure consumer](../examples/databento_consumer.py) injects literal synthetic wire bytes and a placeholder credential; it never contacts Databento.

The ordinary trade mapping preserves int64 UTC nanoseconds, fixed integer prices, provider sequence, quantity and explicit eligibility/known-at. Source event identity binds publisher/instrument/event/sequence; input identity also binds response SHA256, profile and chunk row selection. All capture-range records pass full canonical order/duplicate/schema validation before event filtering and before any delivery. The canonical population uses event `[start,end)`; the upstream trade request uses capture `[start,end)`. Default source coverage is `Coverage(None, observed, False)` because capture EOF does not certify event completeness. Caller-declared complete coverage needs a policy identity and exact observed canonical count. Chunk delivery coverage is separate and exact.

BAR records must have the one-minute rtype. End is exactly start+60,000,000,000 nanoseconds; whole intervals must lie within the event selection. OHLC integer coefficients and volume are preserved; undefined OHLC prices map to null and canonical policy checks coherence/zero volume. Trade count and actual notional remain null, so no fabricated bar VWAP. Unknown/future known-at remains unknown/future. No missing-minute interpolation, live/replay, quotes/reference/daily, batch jobs, cache, redirects, pagination or automatic retry is supported.

`DownloadPolicy` defaults to10 wire records,512 KiB logical body,64 KiB metadata,16 KiB reads,1024 rows/batch and30 seconds. Request/approval caps can tighten limits. The fixed TLS host makes one POST form request with explicit numeric instruments, uncompressed DBN3 and a finite record limit. Responses reaching that limit fail as potentially truncated. Cancellation/deadline checks run between network stages, reads, records and delivery chunks; socket timeouts refresh with remaining time, including the response-owned socket. Failed read partial bytes are charged. Error bodies are not consumed or logged. These are logical response/row/time bounds, not a total-RSS/TLS-overhead/preemptive guarantee. Provider exceptions are replaced outside handlers by safe typed codes without raw causes/contexts; process memory is outside this public-diagnostic boundary.

Pre-code literal [oracle](../tests/databento_oracle.json) preceded runtime. Local23 synthetic tests, public pure consumer, strict six-file typing, retained32 acquisition and43 file tests passed after correction. Initial tests exposed fixture selection/registry mistakes; initial separate automated source review found three P2 issues (stale response timeout, lost partial-byte accounting, filtered-out invalid records), corrected with three regression tests. Re-review is pending. The first factory regression attempt lacked the optional owned factory fixture distribution; this was an environment setup failure, not a passing test. No numerical/performance/provider/native/release evidence is inferred from these local checks.

The package alone depends on accepted acquisition.a0/I/O SDK.a2 and `databento-dbn==0.70.0`; upstream pure/SDK distributions remain unchanged and light. The inspected Databento SDK0.87.0 is a source reference, not an installed network dependency. Version/licensing: experimental0.1.0a0, Apache-2.0 library code; provider market data rights/fees are separate and must be established before real use. Native workflow builds repeated wheel/sdist archives and fresh installed consumers on Windows/Linux, verifies dependency/license/typing boundaries and61 invariant core files. Actual account/download proof is deliberately absent from synthetic CI.
