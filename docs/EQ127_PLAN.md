## Ownership, transactions and committed visibility

Stable-inode cooperative OS lease per output file serializes full attempts and temporary committed lookup/read operations; it is never replaced/unlinked. Close ALL owned engine connections before releasing lease. At most one active native writer process/owner; other live owners receive BUSY, including other keys/readers. Separate processes may obtain exclusive sequential handoff after close/process exit; simultaneous native multiprocess sharing is unsupported. Capabilities declare serialized_writer and transactional, not conflict_safe_multi_writer. Use native Windows byte locking/Linuxflock on actually qualified local filesystems.

Persist STAGING reservation/content/counts in a separate committed control transaction before starting the data transaction. Ordered whole-unit writes stage threeBLOBs/typedrows; receipt/completion/reservationCOMMITTED become visible in the SAME data COMMIT. Independent same-process control connection proves committed state; never infer success from uncommitted rows on the data connection. Queries use fixed SQL/parameters and explicit ordered complete reads. Before commitment, committed-view lookup reports STAGING and exposes no result; after commitment it verifies and returns the original immutable receipt.

Abort rolls back staged data, then persists ABORTED without dropping the reservation/tombstone. Same content retries use a new exclusive attempt; different content/counts under a reserved key conflict. After terminated owner/WAL recovery, committed receipt replays or uncommitted data rolls back and a new attempt starts. No resumable offset. Foreign/closed handles and noncontiguous ordinals fail. Raw commit uncertainty becomes COMMIT_UNKNOWN and factual committed-view lookup; CORRUPTION remains an error, never masked by apparent recovery. Cancellation/abort cannot retract verified commitment. Close releases owned engine/kernel resources even when abort outcome cannot be proven.

Reservation floor7days is policy while caller preserves the output/namespace, not an elapsed7day test; receipt/read retention has no automatic expiry. Caller owns global storage growth/quota/explicit cleanup. No task/catalog/worker resume behavior is promised.
