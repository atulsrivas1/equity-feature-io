This bounded EQ166 / supporting EQ212 implementation adds representation conversion for the frozen17-output period/extended subset. `equity_feature_duckdb.ef1.PeriodInputs` declares nullable `(calendar_provenance, daily_history, bars)` slots. `ExtendedInputs` declares `(calendar_provenance, bars, prior_close)`. Each has `.roles`, `.slots`, `.batches`, and a corresponding three-cell `.provenance` tuple. Origin labels are `duckdb_backed_observed`, `synthetic`, or `unavailable`; the last requires a missing slot. Covered empty populations remain actual batches. `.batches` retains the declared order while omitting missing slots. Frozen containers retain the supplied batch objects, columns and complete metadata; prior DAILY rows retain their original predecessor session, never the target session.

`make_period_batch(kind, column_order, rows, metadata=...)` performs exact rectangular row-to-column conversion with concrete tuples and original canonical metadata. Empty populations retain explicitly supplied column names. It does not create OHLC, aggregate bars, construct prior closes, filter fields, infer coverage or repair availability. Generic canonical structural validation examines every supplied column. It does not apply the target regular SessionSpec to legitimate extended timestamps or predecessor DAILY rows. Calculations independently validate actual calendar selection, declared scopes, temporal coverage, cutoffs and mathematics.

The three slot kinds are REFERENCE/DAILY/BAR for periods and REFERENCE/BAR/DAILY for phases. TRADE-to-phase conversion is unsupported. Distinct original input IDs and consistent namespace/instrument are required; prior session IDs legitimately differ. Calendar and market source publishers can differ. No fabricated source agreement or common revision is imposed across independent publishers. Available, missing, partial, unknown and future-known inputs remain separate representations.

Public `synthetic_period_fixture()` / `synthetic_period_config()` / `synthetic_period_context()` return the exact PERIOD_BASE source/config/context. The equivalent `synthetic_extended_*` helpers return EXTENDED_BASE. These are fresh, explicit synthetic examples, with no N: source qualification. EXTENDED_BASE has two phase bars and preceding close5; it is distinct from the retained original one-bar E01 fixture. Helpers contain no expected output calculation. Workers orchestrate execution and use the unchanged canonical sink to write a separate new output DuckDB. Source databases remain separate.
